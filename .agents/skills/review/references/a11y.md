# Checklist — accessibilité (RGAA 4.1.2 / WCAG 2.2 AA, via ultra11y)

Périmètre : **toute revue** (modes gates et pr), quel que soit le diff — jamais `skip`. Sans `.tsx` / `.scss`, `review-a11y` tourne quand même (`--since <BASE>`) : son passage statique et `affected` couvrent les fichiers non UI qui changent le rendu (composants et hooks `.ts`, i18n / messages, constantes, CSS modules, routes) ; verdict PASS ou ses constats.

**ultra11y fait la revue, ce fichier ne la refait pas.** Le skill `review-a11y` porte la méthode et ses règles (ne jamais inventer une non-conformité, critères de rendu en risque résiduel, préexistant hors verdict). Ici, seulement ce qui est propre à egapro. C'est le seul contrôle d'accessibilité du dépôt : aucun workflow GitHub Actions ne le rejoue (l'audit RGAA complet est le bot iterion Acci, hors dépôt).

## 1. Lancer `review-a11y`

```bash
test -f .agents/skills/review-a11y/SKILL.md || pnpm install      # symlink vers la devDependency : absent = node_modules absent
```

Invoque le skill `review-a11y` sur la branche, `--since <BASE>` (la base de l'étape 1 du mode gates), moteur de `packages/app` (`pnpm --filter app exec ultra11y …`). Ton outil n'expose pas le skill → lis `.agents/skills/review-a11y/SKILL.md` et suis-le à la lettre. Passe `--lang fr` aux commandes du moteur et rends son rapport **tel quel**, en français ; ses constats RGAA alimentent la ligne `accessibilité` du tableau des gates et la liste des constats.

- **§1 (statique sur le diff)** : toujours.
- **§1b (rendu des pages touchées)** : quand une URL existe pour la branche **et** pour la base. Sur une PR poussée, ce sont les préversions kontinuous : `https://<sous-domaine de la branche>.ovh.fabrique.social.gouv.fr` et `https://egapro-alpha.ovh.fabrique.social.gouv.fr` (la base). En local avant push, un `pnpm --filter app build && pnpm --filter app start` de la branche face à la préversion de `alpha`. Aucune des deux → saute §1b et garde les critères de rendu en risque résiduel.

L'audit RGAA complet (toute la grille, adjugée) n'est pas ici : c'est le bot iterion Acci, chaque lundi ou par `/acci` sur la PR ([`docs/accessibilite-ultra11y.md`](../../../../docs/accessibilite-ultra11y.md)).

Une seule version existe côté dépôt : la devDependency de `packages/app`. Le skill **est** cette devDependency, il ne peut pas dériver. (Le bot iterion du run hebdomadaire épingle son propre moteur : « Bump de version » du même document.)

## 2. Ce que la CI ne verra pas — à nommer en risque résiduel

- Le rendu de la PR ne voit que ce que la préversion ouvre sans connexion : un écran derrière ProConnect ou gardé par la machine à états du tunnel est « non mesuré » des deux côtés, donc non bloquant. Contraste, focus visible, zoom et reflow de ces écrans ne se mesurent que par la suite Playwright `src/e2e/a11y/` (`pnpm --filter app test:e2e:a11y`, en local) : un diff qui les change se signale en risque résiduel, avec les écrans touchés.
- Ce que `affected` liste comme non résolu (route dynamique sans URL connue) ou non rattaché (fichier qui n'atteint aucune page) est **non rendu**, jamais propre.
- Une page ajoutée n'est capturée par la suite `src/e2e/a11y/` que si elle est déclarée dans `sample.pages` de `packages/app/.ultra11yrc.json` (ou exemptée dans `sample.exempt` avec sa raison) : rien ne le vérifie sur la PR. Une route nouvelle absente des deux se signale avec l'entrée à ajouter.
- Les critères de jugement (pertinence d'un `alt`, intitulé de lien en contexte, logique clavier d'un composant) ne sont tranchés que par cette revue ; rien ne les recontrôle avant l'audit Acci du lundi (ou un `/acci`).

## 3. Interdits

- Couper un garde-fou (`SKIP_A11Y=1`, `ULTRA11Y_HOOK=off`, `"hook": { "failOn": "off" }`) sans l'accord de l'utilisateur. Le hook Claude Code / plugin OpenCode n'est qu'un rappel ; la barrière est le pre-commit et `pnpm verify`.
- Retirer la devDependency `ultra11y` (aucun `import` ne la cite : c'est le binaire et `ultra11y/playwright`), remettre `@axe-core/playwright`.
- Toucher à `.ultra11yrc.json`, `.ultra11y/` ou à la version sans avoir lu [`docs/accessibilite-ultra11y.md`](../../../../docs/accessibilite-ultra11y.md).

## Sortie

Le rapport `review-a11y`, puis le verdict pour la table des gates :

- `PASS` — aucune non-conformité (des risques résiduels peuvent rester, nommés).
- `NEEDS WORK` — au moins une non-conformité bloquante.
- `MINOR` — seulement des non-conformités majeures ou mineures.
