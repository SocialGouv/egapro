# Checklist — accessibilité (RGAA 4.1.2 / WCAG 2.2 AA, via ultra11y)

Périmètre : tout `.tsx` du diff. Aucun → `skip — no UI files`.

**ultra11y fait la revue, ce fichier ne la refait pas.** Le skill `review-a11y` porte la méthode et ses règles (ne jamais inventer une non-conformité, critères de rendu en risque résiduel, préexistant hors verdict). Ici, seulement ce qui est propre à egapro.

## 1. Lancer `review-a11y`

```bash
test -f .agents/skills/review-a11y/SKILL.md || pnpm install      # symlink vers la devDependency : absent = node_modules absent
```

Invoque le skill `review-a11y` sur la branche, `--since <BASE>` (la base de l'étape 1 du mode gates), moteur de `packages/app` (`pnpm --filter app exec ultra11y …`). Ton outil n'expose pas le skill → lis `.agents/skills/review-a11y/SKILL.md` et suis-le à la lettre. Rends son rapport **tel quel**.

Une seule version existe : la devDependency de `packages/app`, tenue égale à l'Action CI par `a11y-version-coherence`. Le skill **est** cette devDependency, il ne peut pas dériver.

## 2. Ce que la CI ne verra pas — à nommer en risque résiduel

- `a11y-lite` ne juge que les constats de rendu **nouveaux**, et ne recapture que les pages que le graphe d'imports relie au diff. Un fichier qui change le rendu partout sans être importé par une page (layout racine, styles globaux, `middleware.ts`, config de build, dépendances DSFR) doit figurer dans `sample.global` de `packages/app/.ultra11yrc.json`, sinon aucune page n'est recapturée : un tel fichier dans le diff, absent de `sample.global`, se signale en risque résiduel avec la ligne à ajouter.
- Les critères de jugement (pertinence d'un `alt`, intitulé de lien en contexte, logique clavier d'un composant) ne sont tranchés que par cette revue ; au rendu, rien ne les recontrôle avant le cron du lundi.

## 3. Interdits

- Couper un garde-fou (`SKIP_A11Y=1`, `ULTRA11Y_HOOK=off`, `"hook": { "failOn": "off" }`) sans l'accord de l'utilisateur. Le hook Claude Code / plugin OpenCode n'est qu'un rappel ; la barrière est le pre-commit et la CI.
- Retirer la devDependency `ultra11y` (aucun `import` ne la cite : c'est le binaire et `ultra11y/playwright`), remettre `@axe-core/playwright`.
- Toucher à `a11y*.yaml` ou à la version sans avoir lu [`docs/accessibilite-ultra11y.md`](../../../../docs/accessibilite-ultra11y.md).

## Sortie

Le rapport `review-a11y`, puis le verdict pour la table des gates :

- `PASS` — aucune non-conformité (des risques résiduels peuvent rester, nommés).
- `NEEDS WORK` — au moins une non-conformité bloquante.
- `MINOR` — seulement des non-conformités majeures ou mineures.
