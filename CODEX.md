## Business context

EGAPRO is the French government platform for declaring gender pay equity indicators (7 indicators, detailed in [README.md](./README.md)).

Key concepts for development:
- **Indicators A–F**: pre-calculated by GIP-MDS from DSN data, available each March
- **Indicator G**: company-calculated pay gap by job categories (base + variable compensation)
- **Alert threshold**: gap >= 5% triggers additional obligations (second declaration, CSE opinion, joint assessment)
- **CSE opinion**: PDF upload, companies >= 100 employees only, up to 4/year
- **Company sizes**: < 50 (voluntary), 50–99 (triennial), >= 100 (annual + CSE required)

All business rules are centralized in `packages/app/src/modules/domain/` as pure TypeScript functions. See `packages/app/CLAUDE.md` for details.

Full specs: <https://github.com/SocialGouv/egapro/wiki/Spec-V2>

## Git hygiene

  - `Co-Authored-By: Codex …`
  - `Co-Authored-By: Claude …`
  - `Generated with Codex`, `Generated with Claude Code`, or any AI footer
  - Any mention such as "generated by AI / bot / Codex / Claude" in public GitHub artifacts
- **No sensitive data** committed: `.env`, credentials, secrets, API keys. Verify before every push.

## Public repo — GitHub artefact hygiene

`SocialGouv/egapro` is a **public** repository. Anything an agent posts (issue body/title, PR body/title, comments, review threads, commit messages, branch names) is immediately public, indexed by search engines, and mirrored on forks.

**Hard rule — secrets/tokens**: zero paste, never. GitHub tokens (`ghp_`, `github_pat_`), LLM keys (`sk-ant-`, `sk-proj-`, `sk-`), AWS/GCP keys, JWTs (`eyJ...`), connection strings (`postgres://user:pwd@...`), `.env` values, `kubectl get secret` output, `Authorization: Bearer ...` headers must always be referenced by role and never by value, even truncated.

Before posting, also scrub: test logins, PII (emails, names, real SIRENs), internal infra identifiers, raw `kubectl logs`, and stack traces that reveal internal observability details. See `.claude/rules/git-artefact-hygiene.md` for the exhaustive list and response procedure if a leak happens.

| Gate | When | How |

## Agents and skills

### Pipeline principal : conception → exécution

```text
/analyse [<issue#>|<description>]    →    /implement <issue#>
──────────────────────────────────         ───────────────────
 Feature → product-owner + architect       Feature → epic_loop.sh background
 Task    → architect mode task             Task → code-dev sync foreground
 Bug     → bug-analyst                     Bug  → code-dev sync foreground
```

These workflows are implemented in `.claude/skills/` and `.claude/agents/`. Codex should not invent alternate repository processes when the existing one already defines the expected flow.

### Agents (`.claude/agents/`)

**Conception pipeline**:

| Agent | Role |
|---|---|
| `product-owner` | Refines the need and writes PO scenarios on epics |
| `architect` | Handles epic/task analysis modes |
| `bug-analyst` | Reproduces and diagnoses bugs |

**Execution pipeline**:

| Agent | Role |
|---|---|
| `code-dev` | Implements a ticket end-to-end |
| `functional-validator` | Replays PO scenarios against the dev server |
| `doc-writer` | Regenerates `docs/*.md` from current code state |

**Review pipeline**:

| Agent | Role |
|---|---|
| `review-fixer` | Addresses human and bot review comments on PRs |

**Quality gates**:

| Agent | Role |
|---|---|
| `validator` | Typecheck + test + lint + format |
| `structural-auditor` | Structural audit |
| `rgaa-auditor` | Accessibility audit |
| `security-auditor` | Security review |

### Skills (`.claude/skills/`)

| Skill | Purpose |
|---|---|
| `/analyse [<issue#>] [<description>]` | Conception phase: detect mode and invoke the right analysis agents |
| `/implement <issue#>` | Execution phase: dispatch epic/task/bug implementation |
| `/report [<N> ...]` | Live dashboard of active agents and epic state |
| `/open <PR>` | Recreate a local worktree for a PR |
| `/review [<issue#>|<PR#>]` | Address review comments on one or more PRs |
| `/doc [<issue#>]` | Regenerate user-facing documentation from current code |

Workflow baseline: `/analyse <issue>` for conception, then `/implement <issue>` for execution, then `/review` when humans comment on PRs. `/doc` regenerates docs from code.

### Orchestration (`scripts/orchestration/`)

The repository already ships orchestration scripts for the epic workflow. Important entry points:

| Script | Role |
|---|---|
| `epic_loop.sh` | Background loop driver for epic execution |
| `ensure_epic_branch.sh` | Ensures `epic/<N>` integration branch exists |
| `merge_validated_ticket.sh` | Squash-merges a validated ticket PR into `epic/<N>` |
| `rebase_epic_branch.sh` | Rebases `epic/<N>` onto `origin/alpha` between ticks |
| `open_epic_final_pr.sh` | Opens or reuses final `epic/<N> -> alpha` PR |
| `run_doc_writer.sh` | Invokes the documentation regeneration workflow |
| `cleanup_terminal_worktrees.sh` | Removes stale ticket worktrees |
| `dispatch_plan.sh` | Computes dispatchable tickets for an epic |
| `process_tick_result.sh` | Applies board mutations from `code-dev` results |
| `set_ticket_status.sh` | Encapsulates board status changes |
| `create_linked_branch.sh` | Creates a branch linked to a GitHub issue |
| `force_pr_issue_link.sh` | Forces closing issue references to populate |
| `open_worktree.sh` | Recreates a worktree for a PR |
| `cache_gh.sh` | Caches `gh` calls to mitigate rate limits |
| `log_event.sh` | Append-only agent logging |
| `epic_state.sh` | Compact state table for epic sub-tickets |
| `render_dashboard.sh` | Dashboard backing `/report` |

Codex should reuse these scripts when the user explicitly asks to follow the repository's automation flow.
